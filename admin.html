Deploying & managing Trace

Trace is built to be fleet-managed. Every support-facing detail — helpdesk links, ticket templates, announcements, branding — can be pushed and locked with a standard configuration profile from Jamf, Intune, Kandji, Mosyle, or any MDM. This page is the complete reference.

1.How management works

Trace reads macOS managed preferences on its preference domain:

com.patrickramagge.trace

Any MDM that can deliver a custom settings payload on that domain can configure Trace. Three behaviours to know:

  • Profile-delivered keys are forced. Values arriving via configuration profile appear in the app and lock: the Settings → Support pane switches to a read-only "managed by your organization" view. Users cannot override them.
  • Changes apply live. Trace watches for preference changes — pushing an updated profile updates the running app within seconds. No relaunch, no logout.
  • Removal restores user control. Remove the profile and the fields unlock, reverting to whatever the user had set (usually nothing).
Set-once vs. forced: values written with defaults write or a script populate the same fields but remain user-editable — useful for suggestions, wrong for enforcement. Only profile-delivered (MCX/forced) preferences lock the UI.

2.Quick start (10 minutes)

  1. Download Trace-ManagedSettings.mobileconfig below.
  2. Open it in a text editor and replace the example values (organization name, portal URL, email, phone, ticket template, announcement).
  3. Install it on one Mac by double-clicking → System Settings → General → Device Management → Install, and launch Trace to confirm: the panel shows your announcement banner; the Support window shows your branding; Settings → Support shows everything locked.
  4. Upload the same payload to your MDM (per-MDM steps in section 7) and scope it.
  5. Deploy the app itself via Apps & Books (section 6).

3.Complete key reference

All keys are optional — anything you don't set simply hides in the app. Strings are shown to users verbatim, so they're localisation-ready from your side.

Alert & compliance keys

Every notification the app can send is manageable. Forcing any key locks the matching control in Settings → Alerts ("Managed by your organisation") and applies live. Frequency values, from gentle to insistent: once · every15Minutes · every30Minutes · every45Minutes · hourly · every2Hours · daily · every3Days · weekly — once notifies when a condition starts and re-arms when it clears.

KeyTypeWhat it does
storageAlertEnabledbooleanDisk-usage alerts on/off.
storageAlertThresholdPercentintegerNotify above this usage. 50–99, default 90.
storageAlertFrequencystringRepeat cadence. Default daily.
uptimeAlertEnabledbooleanRestart reminders on/off.
uptimeAlertDaysintegerRemind after this many days up. 1–30, default 7.
uptimeAlertFrequencystringRepeat cadence. Default daily.
batteryAlertEnabledbooleanLow-battery alerts on/off (portables; ignored on desktops).
batteryAlertThresholdPercentintegerNotify below this level while discharging. 5–50, default 15.
batteryAlertFrequencystringRepeat cadence. Default once (re-arms when charged).
softwareUpdateAlertEnabledbooleanmacOS update reminders on/off (public SOFA release feed).
softwareUpdateAlertFrequencystringRepeat cadence. Default every3Days. Set hourly or faster to apply real pressure.
UpdateDeadlineDaysintegerPatch window in days after a macOS release (e.g. 14 for Cyber Essentials+). Reminders escalate to at least daily in the final 3 days and once overdue — a faster configured cadence is kept. Notifications carry "Open Software Update" and a 24-hour snooze. 0/unset = off.
healthAlertsEnabledbooleanSustained memory pressure (>5 min), thermal throttling (>2 min), battery capacity below 80%.
healthAlertFrequencystringRepeat cadence. Default daily; battery-health notices additionally capped at one per 30 days.
Fleet visibility: two ready-made Jamf Extension Attributes (downloads below) report each Mac's update pressure — "Up to date" / "Behind: 26.2 available (11 days)" — and whether Trace is running, using the same cached release data the deadline escalation runs on.

4.Ticket URL templates

The ticket link pre-fills your ITSM tool with device facts so users never have to find their serial number. Placeholders are substituted (and percent-encoded) on the device at click time:

PlaceholderSubstituted withExample
{serial}Hardware serial numberC02XK1ZGJGH5
{model}Model identifierMac16,1
{os}macOS version26.1.2
{hostname}Computer namePAT-MBP-0231
{username}Short login namek1506283

Worked example for a generic ITSM intake form:

https://helpdesk.example.ac.uk/new?category=mac&serial={serial}&os={os}&host={hostname}&user={username}

Pair it with the user-side "Copy for ticket" button, which puts a formatted plain-text block (device, session and network details) on the clipboard for pasting into the ticket body.

5.Announcements

The announcement banner is a lightweight broadcast channel: it appears at the top of every managed Mac's panel the next time the panel opens after the profile lands.

  • Dismissal is per-message. Trace remembers the exact text the user dismissed. Pushing a profile with different text shows the new banner; re-pushing identical text stays hidden.
  • To re-show the same notice, change the text trivially (add a date: "Maintenance Sat 08:00–12:00 (reminder)").
  • To retract a notice, push the profile with AnnouncementMessage removed or empty.
  • If AnnouncementURL is set, the banner becomes clickable and opens it.
Keep messages to one or two lines — the banner wraps up to three lines and is meant for "heads-up" notices, not essays.

6.Deploying the app itself

Trace is distributed through the Mac App Store, so the supported fleet path is Apps & Books (VPP):

  1. In Apple Business Manager / Apple School Manager → Apps & Books, search for Trace and acquire licenses (free apps still require licenses).
  2. In your MDM, deploy it device-assigned — no Apple ID required on the Mac, installs silently.
  3. Scope the configuration profile to the same devices so the app is branded from first launch.

Launch at login

ForceLaunchAtLogin registers the login item when the app launches — a freshly installed app that has never run can't register itself. Pair the install with a one-time launch, e.g. a Jamf policy or post-install script running:

open -a "Mac Trace"

From then on it starts at every login. Users see a standard "Mac Trace added as a login item" notification from macOS — expected behaviour.

7.Per-MDM walkthroughs

Jamf Pro — Option A: custom schema (recommended)

  1. Computers → Configuration Profiles → New.
  2. Add the Application & Custom Settings → External Applications payload → ＋ Add → Source: Custom Schema.
  3. Preference Domain: com.patrickramagge.trace.
  4. Paste the contents of Trace-Jamf-Schema.json into the schema box.
  5. Jamf renders a friendly form — fill in your values, scope, save. Done.

Jamf Pro — Option B: plist upload

Same payload → Source: Upload → domain com.patrickramagge.trace → upload an edited Trace-Settings-Example.plist.

Microsoft Intune

  1. Devices → macOS → Configuration profiles → Create profile → Templates → Preference file.
  2. Bundle ID: com.patrickramagge.trace.
  3. Upload the edited Trace-Settings-Example.plist, assign to your device groups.

Kandji, Mosyle, Addigy, others

Use each product's Custom Profile feature with the edited Trace-ManagedSettings.mobileconfig — it's a standard custom-settings payload, nothing exotic. Kandji: Library → Custom Profile. Mosyle: Management → Certificates/Profiles → Custom Profile. Addigy: Policies → Profiles → Custom.

8.Testing & verification

On a test Mac, without an MDM

  1. Edit the example .mobileconfig and double-click it.
  2. System Settings → General → Device Management → install it.
  3. Launch Trace and confirm: the announcement banner appears in the panel; the Support window is branded; Settings → Support is read-only.
  4. Remove the profile and confirm everything unlocks.

Verifying on a managed device

# Is the profile present?
sudo profiles show | grep -A4 patrickramagge

# What does the app actually see? (forced values appear here)
defaults read com.patrickramagge.trace OrganizationName

In the app, the definitive signal is Settings → Support showing "managed by your organization" — that means the keys arrived as forced preferences, not just written values.

9.Troubleshooting

SymptomLikely cause & fix
Values don't appear at allDomain typo (must be exactly com.patrickramagge.trace), or the profile isn't scoped to the device. Check sudo profiles show.
Values appear but aren't lockedThey were delivered as "set once" or by script rather than as a forced profile payload. Use the configuration-profile route; defaults write never locks.
Announcement doesn't reappearThe text is identical to one the user already dismissed. Change the wording (even a date suffix) to re-show.
Ticket link opens with raw {serial}Placeholder typo — they're case-sensitive and brace-wrapped: {serial}, {model}, {os}, {hostname}, {username}.
App doesn't start at login despite ForceLaunchAtLoginThe app hasn't been launched once since install — registration happens at launch. Add a one-time open -a "Mac Trace" policy.
Support section shows old values after a pushUpdates apply within seconds while the app runs; if the Mac was asleep during the push, they land on wake. Worst case, quit and relaunch Trace.

10.Notes for security review

  • No telemetry. Trace collects and transmits nothing. Its network traffic is two anonymous HTTPS GETs: the public macOS-release feed sofafeed.macadmins.io (the same source used by Nudge, at most every six hours) and — only when a user clicks "Check for Updates" — Apple's public itunes.apple.com lookup. Neither carries device-identifying data.
  • Sandboxed, hardened runtime, Mac App Store reviewed. No kernel extensions, no privileged helpers, no background daemons beyond the app itself.
  • Local-only device data. Serial, IP, username and the rest are read locally and leave the device only via the user's own clipboard ("Copy for ticket") or the ticket URL the user clicks — both user-initiated, both going to your configured endpoints.
  • Management is one-way. Trace reads managed preferences; it reports nothing back to the MDM or anywhere else.
  • Privacy policy: traceapp privacy.
